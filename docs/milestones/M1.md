# M1 访问时间限制

## 状态

**进行中。** 时间规则内核已完成；后续按五个阶段推进。纯 UI 壳提前到无障碍服务接入之前实现，每阶段完成自动化验证、代码评审和对应验收后再进入下一阶段。

## 目标

只允许孩子在每天指定时段访问豆包。M1 默认允许时间为 `07:20～20:30`，包含 07:20，不包含 20:30；时间内所有豆包入口直接放行，时间外实时拦截，豆包持续前台跨过 20:30 时立即收回。

## 用户流程

```text
孩子打开受控“豆包”入口 → 查看当前规则 → 点击打开官方豆包
时间内进入豆包 → AccessRuleEngine 放行 → 显示时段剩余倒计时
时间外进入豆包 → BACK 拦截 → 显示下一次开放时间
豆包前台到达 20:30 → 重新裁决 → 隐藏胶囊 → 逐层退出豆包
Debug 临时授权存在 → 优先按 M0 授权放行和计时
```

## 核心行为

- 正常孩子访问不创建或消费 `LaunchAuthorizationState`，直接由 `AccessRuleEngine` 按设备本地时间裁决。
- 有效的 Debug 临时授权优先于时间规则，使 30 秒和 10 分钟入口可以在时间外独立回归 M0；Release 没有该授权入口。
- 时间允许时从桌面、搜索、最近任务、深链接和受控首页进入豆包均直接放行；时间禁止时均复用现有 BACK 拦截管线。
- 豆包前台时安排关闭边界任务。任务触发后重新读取时间并严格确认豆包仍为活跃窗口，再执行一次主 BACK 和必要的精准补发。
- 豆包离开前台、锁屏或服务销毁时取消边界任务；返回前台时重新裁决并重新调度。
- 系统时间、时区或日期发生变化时立即重新计算，避免通过修改时间绕过规则。
- 正常规则放行时胶囊实时显示 `时段剩余 H:MM:SS`；Debug 授权继续显示 `剩余 MM:SS`，两者不同时出现。

## 接口与架构

- `AccessPolicy` 保存目标应用规则；M1 包含 `DailyTimeWindow(startInclusive, endExclusive)`，默认 `07:20～20:30`。
- `AccessDecision` 在 M1 提供 `Allowed(closesAt, remainingMs)` 和 `OutsideAllowedWindow(nextOpeningAt)`；M2 在同一类型中增加每日额度耗尽结果。
- `AccessRuleEngine` 是纯 Kotlin 规则内核，输入策略、`Instant` 和 `ZoneId`，输出准入结果，不直接读取 Android 系统时间。
- `TimeWindowAccessController` 负责前台生命周期、墙上时间边界和主线程调度；边界回调必须重新裁决并保持幂等。
- `GateAccessibilityService` 的准入顺序固定为：有效 Debug `LaunchAuthorizationState` → `AccessRuleEngine` → 放行或现有拦截状态机。
- 覆盖层抽象为可显示任意状态文本的时间胶囊，继续复用同一 View，只更新文字与警示颜色。

## 分阶段实施

### 1. 时间规则内核（已完成）

- 新增时间窗口、策略、裁决结果和纯 Kotlin `AccessRuleEngine`。
- 开始边界包含、结束边界排除；支持跨午夜窗口，`start == end` 视为非法配置。
- 完成时间边界、下一次开放时间和时区单元测试；本阶段不改变 M0 运行行为。

### 2. 豆包风格纯 UI 壳

- 启动器名称改为“豆包”；使用参考图风格的原创女性头像图标，并添加明显的蓝色锁角标。无障碍服务名称继续为“豆包访问守卫”。
- 首页参考用户提供的豆包截图实现顶部标题、浅灰内容卡、横向快捷入口和底部启动栏，但不实现聊天或伪造对话。
- 建立独立 `HomeUiState` 和无状态 Compose 页面，覆盖允许、禁止、服务未接入、目标应用未安装等展示状态；页面只通过回调发出启动、菜单和设置动作。
- 左侧菜单展示默认规则、无障碍状态、官方豆包安装状态及设置入口，并明确该应用是打开官方豆包的受控入口。
- Debug 构建长按首页“豆包”标题 5 秒进入隐藏的 M0 诊断页；Release 不注册该入口。
- 本阶段不把 UI 裁决当作安全边界：Release 普通启动入口显示“访问控制接入中”并禁用；Debug 继续通过隐藏诊断页回归原有 30 秒和 10 分钟临时授权。

### 3. 无障碍服务接入

- 新增时间窗口控制器和关闭边界调度，接入豆包前后台、锁屏解锁、服务重连及系统时间变化。
- 正常时间规则与 Debug 临时授权按既定优先级裁决。
- 扩展顶部胶囊为“时段剩余”和“临时授权剩余”两种模式。
- 时间外和到点收回复用 M0 已验证的多层 BACK、三态活跃窗口检查和延迟补发。
- 本阶段以无障碍服务对所有豆包入口的真实裁决为完成标准，不依赖受控首页是否处于前台。

### 4. UI 真实状态与准入绑定

- 使用 `AccessRuleEngine` 和设备当前 `Instant`、`ZoneId` 生成真实 `HomeUiState`，显示当前是否允许、默认时段和下一次开放时间。
- 所有快捷入口和底部栏共用同一准入启动动作；移除“访问控制接入中”占位，时间允许时启动官方豆包，时间禁止时留在首页并展示下一次开放时间。
- UI 与无障碍服务共用同一份 `AccessPolicy`，但无障碍服务始终是最终安全边界，不能依赖受控首页阻止桌面、搜索、最近任务或深链接入口。
- 系统时间、日期或时区变化以及 Activity 恢复时刷新页面状态，确保展示结果与服务裁决一致。

### 5. 整体回归与收口

- 回归所有 M0 授权、暂停恢复、到期、多层退出和窗口噪音场景。
- 完成 HONOR GT 时间边界、系统时间变化、新图标和新首页真机验收。
- 更新 README、ROADMAP 和 `docs/validation/M1.md`，通过评审后标记 M1 完成。

## 自动化测试

- 规则边界：07:19:59 禁止、07:20:00 允许、20:29:59 允许、20:30:00 禁止。
- 下一次开放时间：开放前返回当天 07:20，关闭后返回次日 07:20；覆盖跨午夜窗口和不同时区。
- 控制器：任务替换、离开/锁屏取消、返回重排、提前触发重算、重复回调幂等。
- 优先级：有效 Debug 授权覆盖时间禁止；无有效授权时严格使用时间规则。
- 安全性：到点时其他应用前台不发送 BACK，豆包前台才允许进入拦截管线。
- UI 纯函数：规则状态、下一次开放时间和时段倒计时格式。
- UI 壳：允许、禁止、服务未接入和未安装状态渲染；所有可见启动入口只触发同一回调；Release 在服务接入前不能启动官方豆包。
- UI 绑定：同一时间与时区下，首页 `HomeUiState` 和无障碍服务必须得到一致的 `AccessDecision`。
- 每阶段运行 `testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleRelease` 和 `git diff --check`。

## 真机验收

- 07:19 无法进入、07:20 可以进入、20:30 豆包前台时在 1 秒内开始退出。
- 主页、会话和视频多层页面跨过 20:30 均能完整退出且不穿透其他应用。
- 到点瞬间切后台不误发 BACK；锁屏跨过结束时间，解锁后不能继续使用。
- 系统时间和时区从允许范围调整到禁止范围时立即收回，反向调整后可以重新进入。
- 荣耀桌面、系统管理器和输入法窗口噪音不改变裁决或重复调度。
- 时段胶囊每秒更新且无闪烁；Debug 临时授权和原 M0 到期流程保持正确。
- 桌面图标清晰、不裁切，锁角标可以与官方豆包区分；首页在目标机字号与比例下不遮挡主要操作。
- 纯 UI 壳阶段确认 Release 启动入口不会绕过尚未接入的服务；完成真实绑定后再验收首页启动、桌面、搜索、最近任务和深链接的一致准入行为。

## 范围边界

- M1 不使用 DataStore，不记录或持久化每日使用时长；每日累计额度属于 M2。
- M1 不提供时间段编辑、生物识别、家长不限时使用或奖励时长；这些能力属于 M3。
- M1 不实现九九乘法挑战，属于 M4。
- 视觉壳不实现聊天、内容生成或虚构对话，也不隐藏、替换或卸载官方豆包。
- 启动器图标使用原创素材并保留锁角标，不直接复制官方图标文件。
- 纯 UI 壳只定义展示和动作接口，不承担访问控制；在第 3、4 阶段完成前不得将页面显示的“允许”状态视为真实放行能力。
