## 拦截行为验证（五入口）

验收方法：每个入口进入豆包，观察是否 1 秒内回到桌面并显示一次提示；
用 `adb logcat --pid=<pid>` 采集 `GateAccessibility` 标签日志，以事件 `elapsedRealtime`
与 `执行拦截` 日志行的时间差计算拦截延迟。

> 实测说明：应用日志被 MagicOS 加密无法读取，延迟改用端到端口径测量
> （ADB 发出启动命令 -> 高频轮询 `dumpsys window` 直到焦点回到桌面），
> 该口径包含豆包启动耗时，比"事件到达 -> HOME 执行"更保守，仍全部满足 1 秒要求。

## 已知实现边界

- 状态机抑制期 3 秒惰性超时：若 HOME 未生效且期间无新事件，需等下一个目标事件才会再次拦截。
- 服务被杀重建后回到默认未授权状态（Idle），行为与 ROADMAP M0.7 场景一致。
- 提示文案为 M0.3 基础版本，M4 乘法门禁落地时将结合挑战上下文调整。

## 真机调试记录（Android 16 / MagicOS 10 特性）

- **`TYPE_ACCESSIBILITY_OVERLAY` 必须使用无障碍服务自身 Context 的 WindowManager**：
  通过 `applicationContext.getSystemService(WindowManager)` 获取的实例调用 `addView` 会抛异常
  （被防御性 catch 吞掉，表现为拦截生效但提示层不显示）。与官方 `GlobalActionBarService`
  示例保持一致使用服务 Context 后，真机验证 `addView` 成功、窗口正常显示与自动移除。
- **应用日志按进程加密**：`adb logcat --pid=<pid>` 下应用自身日志输出为 HKS 加密块，
  无法直接读取失败原因。Debug 构建通过 `files/overlay_diagnostics.txt` 文件诊断
  （`adb shell run-as com.soapgu.learningappgate cat files/overlay_diagnostics.txt`）。
- **远程触发拦截的方法**：`adb shell am start -n com.larus.nova/com.larus.home.impl.alias.AliasActivity1`
  配合 `adb shell dumpsys window windows | grep ACCESSIBILITY_OVERLAY` 可自动化验证窗口生命周期；
  端到端延迟用设备端循环轮询 `dumpsys window | grep mCurrentFocus` 测量。
- **升级安装后无障碍服务自动重绑**：`adb install -r` 覆盖安装后无需重新开启服务。
